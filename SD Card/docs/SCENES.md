## Implemented contract

- Four fixed definitions: Morning, Night, Arrive and Away. Empty, disabled, automatic trigger off. Enabling automatic behavior is distinct from enabling manual scene use. Morning/Night permit calendar triggers; Arrive/Away permit authenticated presence triggers. Remote scene access starts off and is never inferred from local scene permissions, presence, PIN, voice, pairing or Tailscale enrollment.
- At most eight ordered absolute actions. Only purifier power/display booleans, speed1–3, supported mode names, or the fixed fan absolute button library. Toggle/relative fan commands, duplicate physical properties, inconsistent same-device bindings and purifier Off plus implicitly-powering-on speed/mode are rejected. Runtime still must discover capabilities and prove fan semantics; a syntactically valid action is not permission to transmit.
- Every action contains a 64-hex device binding. The local editor/runtime mints and verifies it from the actual selected configuration, never trusting a caller-supplied arbitrary hash. Definitions/versions/history are one atomic SQLite cache document; corruption is preserved and disables writes. Edits use an optimistic revision. Device names, provider tokens, raw IR and credentials are absent from the scene journal.
- An authorized fresh occurrence is consumed in durable storage before device work. Each individual step is separately persisted as unknown before dispatch. Untouched steps remain not_started, factual results use confirmed/unconfirmed/not_sent/unavailable/skipped_override/cancelled. Restart exposes unfinished runs as interrupted but never resumes them. A previously sent step cannot be repeated; an old process generation cannot finish or resume a run.
- One run at a time, no queue, five-minute **per-scene** cooldown retained across edits/restarts, last40 runs retained. The caller must mint occurrence IDs and preserve observation timestamps; triggers older than15seconds, future triggers and unverified clocks are rejected. The store is not a public scheduling API.
- Editing/disabling any scene invalidates subsequent steps of the current run. Already-dispatched results can still be journaled honestly. The executor has120seconds total,30seconds per dispatch and2seconds bounded cancellation cleanup. Authorization is checked every100ms while awaiting a device and must also be checked by the eventual adapter immediately before transmission. Uncooperative cancellation retains the child handle and disables further runs until restart; no replacement worker or retry. Late authorization callbacks fail after run completion. UI notification failure does not abandon command accounting.
- The production `SceneDevices` dispatcher calls the existing serialized purifier/fan runtimes. Before each send it rechecks the current device binding, capabilities, manual override and source authorization; exceptions/malformed results become unconfirmed, never false success or an invitation to retry. Fan controls remain unconfirmed because the IR hardware has no readback.

## Trigger monitor contract

Presence uses boot-local monotonic observations of a specific authenticated paired phone. First sample, changed pairing identity, unknown evidence, untrusted clock, backwards monotonic time or a worker gap longer than5seconds establishes a new baseline. None of those events means arrival. A genuine continuously observed transition requires30seconds connected for Arrive or180seconds disconnected for Away; flapping cancels the candidate. PIN/private-display state, Tailscale and token refresh must not be used as presence evidence. Integration must distinguish known disconnection from Bluetooth adapter/provider failure.

Calendar input is the merged selected-calendar exact-title Sleep interval containing now, or None when awake. The caller must supply fresh calendar data and a revision representing the selected calendars/title. Only a continuously observed crossing of a start/end emits Night/Morning. Boot, stale data, selection edits, suspended worker, wall-clock jump and deleting an active event before its known end do not replay a missed scene. Extending a merged sleep interval does not wake early. This monitor does not replace the existing display ramp/sleep state machine or authorize a scene from temporary touch wake.

## Purifier override correction

`room.py` now stores the one-hour manual suppression deadline independently under room/purifier_override. It survives renaming, selection changes and account disconnect/reconnect. Legacy last-command deadlines are read without startup writes, then preserved transactionally on the next edit/command. Manual command receipt and deadline commit together before dispatch; scene claims refuse an active override and never extend it. Existing local API commands retain the manual default. A malformed override fails closed without overwriting evidence.

### Separate private iPhone scene permission

The local owner-only **Private iPhone actions** panel can grant the restricted Tailscale Shortcut gateway permission to run only selected, already-enabled Morning/Night/Arrive/Away scenes. Granting stores a digest of the full ordered action list including device bindings. Editing, reordering, disabling an action/scene or relinking a device makes that grant ineffective; the owner must review and save it again. A separate reset path handles corrupt permission storage by deleting only that unreadable allowlist and leaving remote access off. The gateway accepts a fixed scene key only, checks trusted time and fresh local device review, journals it as a remote run, and returns a generic acknowledgement; it never reveals private calendar/presence data. It does not expose SSH or the main API. See [TAILSCALE.md](TAILSCALE.md) for the fixed Shortcut payload.
