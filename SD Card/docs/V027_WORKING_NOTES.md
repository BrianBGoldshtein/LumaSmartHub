# 0.2.7 development notes

Branch: `codex/luma-027-development`. This is working source, **not** a signed update or hardware-accepted release. Do not point the Pi updater at this branch. Keep the owner's saved settings on the Pi untouched until a separately reviewed, signed beta is published through the established GitHub workflow.

## Requested outcomes

1. Spoken local timers understand seconds, minutes, and hours, including an optional `titled`/`called`/`named` label. The constrained offline recognizer now has canonical phrases for 1–120 seconds, 1–240 minutes, and 1–4 hours; the unrestricted decoder can capture wording variations and titles. The constrained and unrestricted decoders must agree on the duration before accepting a freely dictated title. Its grammar is 1,840 phrases / about 79 KB, so initial recognizer construction and latency still need Pi 4 measurement. The touch timer and demo preview expose the same duration units and validation; an hour-long countdown displays as `h:mm:ss`. Duration is bounded to 1 second–4 hours; labels are bounded to 40 printable characters. The one active timer remains durable across restart. A spoken request cannot silently replace an existing timer; replacement still requires screen confirmation. Missing or conflicting title recognition asks for a repeat rather than starting an unintended timer.
2. Calendar appointments remain anchored at their **actual** start and end times. Window length adapts to the shortest relevant event and measured screen height: long events can occupy a multi-hour slide, nearby non-overlapping hourly events share a slide instead of leaving a single giant card, and brief events receive fixed half-hour windows. The left ruler labels **only whole hours**, including in close-ups; five-minute guide lines appear in close-up windows. There are no arbitrary 10:20–10:35 rulers or half-hour ruler labels. True simultaneous appointments tag into right-hand lanes, with vertical overlap only for the minutes they actually share; a one-minute card must not manufacture five minutes of overlap. One time interval has one complete view; extra concurrent lanes scroll horizontally inside it, never into competing partial slides. Long card titles may truncate, but tapping always opens the full title. Preserve Google colors, all-day context, and theme styling.
3. The selected bonded iPhone is retried automatically when absent. The LE scan now requests BlueZ `AutoConnect` for the selected address and falls back to a plain LE scan if the option is unavailable; the existing explicit `Device1.Connect` remains. Initial D-Bus connection and BlueZ ObjectManager reads are now bounded, so a stalled service cannot hold the reconnect worker indefinitely. A scan, advertisement, bond, or raw Bluetooth link **never** proves presence: private information unlocks only after successful ANCS Notification Source subscription. iOS controls whether ANCS is published, so the Pi cannot guarantee reconnection solely from proximity. On iPhone, keep Bluetooth on in Settings and Share System Notifications enabled for Luma; Control Center's Bluetooth button can disconnect accessories until the next day.

## Current software evidence

- Full backend suite: 1,286 passed in an isolated Linux copy including the `system/` integration-test fixtures, after the timer grammar, connection scan, and stalled-BlueZ-query changes. The new regression proves an unanswered ObjectManager query times out instead of blocking reconnection forever. An exhaustive test parsed all 728 unprefixed timer grammar phrases into bounded durations. Python dependency deprecation warnings remain.
- Isolated Linux frontend production build and typecheck passed; all 150 frontend tests passed after adding adaptive multi-hour windows, screenshot-inspired staggered overlap/whole-hour-ruler regressions, and seconds/hours timer preview parity. Eight one-hour events fit in two slides at 600px high or one slide at 1080px high. Vite reports a pre-existing large-chunk advisory.
- Headless 1920×1080 and 1024×600 screenshots were inspected for Hearth and Arcade short-event windows. The final 1024×600 render shows the 10:20 and 10:25 appointments in the 10:00–10:30 block; the 10:30 appointment starts the next block. A separate 9:00/9:15 partial-overlap fixture was visually checked in both themes: the 9:15 event tags rightward at 9:15 and only shares the vertical span until the first event ends at 9:25. A two-long-event fixture was checked at both resolutions: one 9:00–17:00 slide has every hour labeled on the left. This is visual QA, not proof of appearance on the owner's touch display.
- Following the owner's Google Calendar example, 1024×600 Hearth and Arcade screenshots confirmed that nearby noon, 2 PM, and 3 PM appointments now share one slide with regular hourly ticks instead of each claiming a near-empty slide. The current-time line was moved behind event cards after it was seen crossing a title in Arcade. A new multi-calendar regression asserts exact starts/ends and separate lanes for the screenshot's staggered overlapping pattern. This is still desktop visual QA, not a Pi-panel acceptance test.
- The touch timer panel was inspected in Hearth and Arcade at 1024×600. In the demo, entering `7 seconds` titled `Stretch` displayed `0:07` and entering `4 hours` titled `Study` displayed `4:00:00`. Demo mode deliberately does not play an alarm; this does not prove Pi speaker behavior.
- No live Pi microphone, timer alarm, Bluetooth reconnect, iOS Settings behavior, or screen viewing-distance test has been performed for 0.2.7.
