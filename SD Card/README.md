# Luma Smart Wall Screen — source and image handoff

This folder contains the Raspberry Pi 4 application source, image builder, documentation and historical build archives. It is not itself a bootable SD card; use Raspberry Pi Imager with a fully built `.img.xz` after confirming the exact target card.

Current release: [0.4.0 Beta](https://github.com/BrianBGoldshtein/LumaSmartHub/releases/tag/v0.4.0), delivered through the signed GitHub updater, not another SD flash. Optional fixed BCM12 control switches an inline USB fan board while all Pi USB ports stay powered. Shared wall/primary-remote settings guide wiring and require an acknowledged, physically observed fan-only test. Installing alone retains the existing USB-hub connection and claims no GPIO. Both modes retain 70°C on / 60°C off; GPIO mode can cool independently in standby. The inexpensive switch defaults off before its controller starts and is not a hardware fail-on thermostat. Software/browser/CI and exact signed install/rollback/download checks passed; actual board/wiring/fan acceptance remains. Keep power connected through update/reboot, confirm 0.4.0 and refresh the phone remote. Settings, accounts, profiles, bonds, grants, timers, games and prior features are retained. See [release notes](docs/V040_RELEASE_NOTES.md), [qualification and Pi Connect steps](docs/V040_WORKING_NOTES.md), [switch ordering/wiring](docs/GPIO_FAN_SETUP.md), [room Wi-Fi](docs/ROOM_WIFI_SETUP.md) and [current status](CURRENT_STATUS.md). Older status/image notes are commissioning history, not the current release.

The owner-tested [r12 image candidate](image/r12-current-916b5d7-20260930/README.md) and [r13 candidate](image/r13-final-71d91b5-20260930/README.md) are historical commissioning artifacts, not the current application version. Keep the existing card and settings for an ordinary application update. [Flashing precautions](docs/FLASHING.md) and [hardware acceptance](docs/HARDWARE_VALIDATION.md) still apply if an OS-level recovery is explicitly needed.

Luma provides a large-type themed dashboard, weather, Google Calendar agenda and tasks, scheduled Sleep behavior, privacy standby based on the paired phone, local Hey Luma commands, timers, optional Levoit purifier control and deliberately opt-in scenes. The Settings area also covers campus networking, Pi Connect, Tailscale private iPhone Shortcuts, encrypted removable settings backups and signed app-only updates. Siri remains on the phone. Account, network and device behavior still need real Pi qualification.

Optional room-device controls support the Levoit Core 300S/300S-P only when discovery confirms the model and capabilities; connecting a purifier does not enable automation. See [room devices](docs/ROOM_DEVICES.md), [scenes](docs/SCENES.md), [campus network](docs/CAMPUS_NETWORK.md) and [signed updates](docs/UPDATE_DEPLOYMENT.md).

Personal credentials and the private release-signing key do not belong in GitHub or this source folder. Application settings are designed to survive in-place app updates, but hardware recovery and rollback must be verified on the owner's Pi. The owner has authorized `main` as the signed Beta update channel; a Beta headline does not mean v1 hardware acceptance. Use Settings → Luma software for application updates, not another SD flash.
