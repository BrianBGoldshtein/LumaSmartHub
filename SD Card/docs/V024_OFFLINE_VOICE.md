# 0.2.4 pleasant offline voice

Status: application path and separately signed asset builder are in source; the actual Pi speaker, memory, latency and rollback checks are **not yet complete**. The owner should not expect a new voice until a release includes both `luma-update-0.2.4.lup` and `luma-voice-kristin-0.2.4.lva` and the asset panel reports **ready**.

The app-only updater has a 24 MiB uncompressed payload limit. Kristin's model, ARM64 Python runtime and Piper corresponding source are about 158 MB, so they cannot safely be hidden in that update. The release sidecar is signed with Luma's existing **offline** Ed25519 key and verified on the Pi with its image-pinned public key. Its model, source archive and every wheel are individually checksum-pinned in `source/tools/voice-assets.lock.json`. The builder rejects unexpected or modified local downloads. The installer rejects duplicate or unsafe archive paths, wrong signature, wrong size/hash, wrong Python/architecture, insufficient disk space and failed local speech synthesis. It installs to a private, version-independent directory beneath `/var/lib/luma/voice-assets`; it does not touch the settings SQLite database or Google authorization. Network access is used only to fetch the one-time release asset. Speech and audio remain in RAM and never go to a cloud speech API.

The `luma-voice` process keeps Piper loaded between replies. It sends bounded text to a local worker, validates 22.05 kHz mono WAV output, and plays through the existing `luma_speaker` sink. If the worker, model or playback fails, speech falls back to the previous `espeak-ng` path; microphone recognition and timer alarms remain separate. The setup page shows check/download/verify/install/ready/failure status, a retry action and a fixed, non-private voice sample.

## Exact external inputs and notices

- [Piper 1.8.0](https://pypi.org/project/piper-tts/1.8.0/) runtime; its [corresponding 1.8.0 source archive](https://pypi.org/pypi/piper-tts/1.8.0/json) is included as `sources/piper_tts-1.8.0.tar.gz` in the signed package. GNU GPLv3 license material is in the wheel's `COPYING` and distribution metadata. The exact ARM64 wheel, source and transitive wheels are recorded with SHA-256 in `voice-assets.lock.json`.
- [Kristin medium voice model](https://huggingface.co/rhasspy/piper-voices/tree/main/en/en_US/kristin/medium), 22,050 Hz. Its [model card](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/kristin/medium/MODEL_CARD) identifies a single female US-English voice trained on public-domain LibriVox recordings; the model repository identifies an MIT license. These source statements should be retained with any public release.
- [ONNX Runtime](https://onnxruntime.ai/), NumPy, and the remaining pinned runtime dependencies are fetched as their official ARM64 wheels. Retain their bundled license metadata when publishing.

## Qualification evidence and remaining gate

The pinned wheels target the image's actual ARM64 Python **3.13**, not 3.11. They installed into an isolated test directory; `numpy`, `onnxruntime` and `piper` imported using the image's ARM64 interpreter in user-mode emulation. A full in-memory synthesis produced a valid 113,708-byte WAV for “Hello, I am Luma.” under emulation. The actual persistent worker also accepted a JSON request and returned a valid 30,252-byte, 22.05-kHz mono WAV for “Hello.” Emulated generation took roughly one minute, which is **not** an estimate of native Pi speed or speaker quality. The signed 158,346,973-byte source-inclusive local test asset verified with the image-pinned key and all 12 file hashes. The test asset has not been published or installed on the Pi.

Before release: test the install/worker/preview/fallback under the packaged ARM64 system, include both assets in one GitHub Release, verify update + persistence/rollback, and audition on the physical screen speaker. If native generation is too slow or thermally costly on the 2 GB Pi 4, retain the fallback and choose a smaller licensed model rather than shipping an unpleasant or unusable default.
