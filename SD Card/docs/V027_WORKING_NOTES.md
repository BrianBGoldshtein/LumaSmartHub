# 0.2.7 development notes

Branch: `codex/luma-027-development`. This is working source, **not** a signed update or hardware-accepted release. Do not point the Pi updater at this branch. Keep the owner's saved settings on the Pi untouched until a separately reviewed, signed beta is published through the established GitHub workflow.

## Requested outcomes

1. Spoken local timers understand seconds, minutes, and hours, including an optional `titled`/`called`/`named` label. Duration is bounded to 1 second–4 hours; labels are bounded to 40 printable characters. The one active timer remains durable across restart. A spoken request cannot silently replace an existing timer; replacement still requires screen confirmation. The constrained and unrestricted decoders must agree on the duration before accepting a freely dictated title. Missing or conflicting title recognition asks for a repeat rather than starting an unintended timer.
2. Calendar appointments remain anchored at their **actual** start and end times. Window length adapts to the shortest relevant event and measured screen height: long events can occupy a multi-hour slide, hourly events can share several hours on a taller screen, and brief events receive fixed half-hour windows. The left ruler still labels **every hour** in a multi-hour slide; five-minute marks appear only in the close-up windows. There are no arbitrary 10:20–10:35 rulers. True simultaneous appointments tag into right-hand lanes, with vertical overlap only for the minutes they actually share; a one-minute card must not manufacture five minutes of overlap. One time interval has one complete view; extra concurrent lanes scroll horizontally inside it, never into competing partial slides. Long card titles may truncate, but tapping always opens the full title. Preserve Google colors, all-day context, and theme styling.
3. The selected bonded iPhone is retried automatically when absent. The LE scan now requests BlueZ `AutoConnect` for the selected address and falls back to a plain LE scan if the option is unavailable; the existing explicit `Device1.Connect` remains. A scan, advertisement, bond, or raw Bluetooth link **never** proves presence: private information unlocks only after successful ANCS Notification Source subscription. iOS controls whether ANCS is published, so the Pi cannot guarantee reconnection solely from proximity. On iPhone, keep Bluetooth on in Settings and Share System Notifications enabled for Luma; Control Center's Bluetooth button can disconnect accessories until the next day.

## Current software evidence

- Full backend suite: 1,284 passed in the Linux test environment after the timer and connection-scan changes; Python dependency deprecation warnings remain.
- Isolated Linux frontend production build and typecheck passed; all 146 frontend tests passed after adding adaptive multi-hour windows, including eight one-hour events that fit in two slides at 600px high or one slide at 1080px high. Vite reports a pre-existing large-chunk advisory.
- Headless 1920×1080 and 1024×600 screenshots were inspected for Hearth and Arcade short-event windows. The final 1024×600 render shows the 10:20 and 10:25 appointments in the 10:00–10:30 block; the 10:30 appointment starts the next block. A separate 9:00/9:15 partial-overlap fixture was visually checked in both themes: the 9:15 event tags rightward at 9:15 and only shares the vertical span until the first event ends at 9:25. A two-long-event fixture was checked at both resolutions: one 9:00–17:00 slide has every hour labeled on the left. This is visual QA, not proof of appearance on the owner's touch display.
- No live Pi microphone, timer alarm, Bluetooth reconnect, iOS Settings behavior, or screen viewing-distance test has been performed for 0.2.7.

## Remaining work before a candidate

- Run updater packaging checks and final diff review before producing a candidate. Verify a named timer at the actual Pi microphone and that its completion alarm sounds after a seconds-level timer.
- Test a real multi-calendar crowded interval in all three themes and at the Pi's actual output resolution. Pay special attention to a short event just before a section boundary and long titles in narrow concurrent lanes. A passing state test is not enough to certify readability.
- On the Pi, test reconnection after walking out of range and returning with iPhone Bluetooth still on, then after a phone-side disconnect. Record Luma's selected-phone status, reconnect attempt time, whether the link appears, whether ANCS becomes authorized, and elapsed time. Do not store the phone MAC in public logs. If BlueZ on the Pi does not support `AutoConnect`, the fallback must still work. Do not claim automatic reconnection fixed from mocks alone.
- Only after hardware feedback and review, prepare the signed beta release on GitHub. Preserve the existing offline signing key and the updater's verified-release policy; no reflash or settings reset is part of this development work.
